# 市场流动性雷达：紧凑布局设计与验收（2026-07-13）

## 问题与根因

旧版使用两个彼此独立的二维 CSS Grid：`01 + 02A/02B` 是第一行，`03 + 04` 是第二行。Grid 的一整行高度由该行最高列决定，因此只把右侧 `02B` 拉高 115px，也会把下一行左侧 `03` 整体向下推；较矮列下方自然形成大块空洞。旧持久化又保存了每张卡片的像素宽度，窗口尺寸变化后会进一步产生横向溢出或不合理留白。

## 新布局契约

- `01、02A、02B、03、04、05、口径` 都是同一个 10 列紧凑网格的直接子模块。
- 默认跨度为：`01=7`、`02A=3`、`02B=3`、`03=7`、`04=3`、`05=10`、`口径=10`。
- 网格使用 `grid-auto-flow: row dense` 和 1px 纵向轨道；每个模块占用的行数等于自身可见高度加 12px，所以同一列的下一模块固定紧贴在前一模块下方约 12px。
- 调整右列高度只会重排右列后续模块，不再通过“整行最高高度”把左列模块推远。
- 横向尺寸以 1–10 列跨度保存，纵向尺寸以像素高度保存；不保存 `top/left` 或空洞位置。
- 页面重新打开时恢复跨度和高度，再根据当前窗口宽度重新打包。因此保留用户尺寸，但不会恢复旧空洞。
- 1180px 以下自动变成单列顺序布局；恢复宽窗口后继续使用此前保存的列跨度。模块强制 `min-width:0` 和 `max-width:100%`，避免网格横向溢出。
- 只有用户明确调整过高度时，图表才切换为“跟随模块高度”的内部布局，单纯调整宽度不会意外压缩图表高度。

1. 校验七个模块都是统一紧凑网格的直接子元素，并核对默认跨度。
2. 校验 10 列、dense、1px 行和 12px 间距的 CSS 合同。
3. 校验本地持久化版本 2 只包含 `span/height`，不包含 `top/left/width`。
4. 用 CSS dense 放置模型模拟 `02B` 从 335px 增高至 450px：`03` 的顶部保持不变；`01→03`、`02A→02B`、`02B→04` 的同列可见间距均为 12px。
