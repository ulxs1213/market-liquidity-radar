# 市场流动性雷达 05B 统一时间游标与悬浮卡 QA

更新日期：2026-07-13
适用模块：05B 当天连续分时 + 成交量 + 资金流 + 五档盘口

## 1. 交互契约

05B 的价格/均价、分钟成交量、累计主力净流/分钟净流变化虽然位于三个 ECharts grid，但共享同一套交易分钟分类轴。鼠标位于任意一个可视区域时：

- 三个 x 轴通过 `axisPointer.link` 锁定同一分钟；
- 三个面板同时显示竖向虚线游标；
- 只显示一张统一悬浮卡，不要求用户分别寻找价格、量和资金；
- 页面内终端和弹窗终端复用同一个 `stockTimeline` DOM 与同一个 ECharts 实例，交互语义完全一致；
- 午休不生成时间点，11:30 与 13:00 在分类轴上相邻；未来分钟保持空白。

统一悬浮卡必须显示：

1. 交易日和分钟；
2. 最新价；
3. 当日均价；
4. 该分钟成交量及股/手口径；
5. 累计主力净流及净流入/净流出方向；
6. 相对上一个真实资金点的本分钟净流变化及方向。

## 2. 真实字段与单位

### 当天实时/最近交易日

价格和成交量来自东方财富公开 `trends2/get`：

| 字段 | 用途 | 页面单位 |
| --- | --- | --- |
| `f51` | 分钟时间 | `HH:MM` |
| `f52` | 最新价 | 元/股 |
| `f56` | 分钟成交量 | 手 |
| `f58` | 当日均价 | 元/股 |

页面同时显示 `约合股数 = f56 × 100`，并明确这是普通 A 股每手 100 股的换算。特殊证券每手规则应以交易所合约为准；换算值不替代上游原始手数。

### 历史分钟

TDX `get_history_minute_time_data` 原始 `vol` 为手，本地历史适配器已乘以 100 后写入 `volume`，因此历史悬浮卡主单位为“股”，并附约合手数。

### 资金

资金来自东方财富 `fflow/kline/get`：

- `f52` 为供应商估算的累计主力净流；
- 本分钟净流变化 = 当前真实资金点 `f52` − 上一个真实资金点 `f52`；
- 第一个可用资金点没有可核验的前值，分钟变化显示 `--`，不得写成 0；
- 正数标注“净流入”，负数标注“净流出”，同时保留符号；
- 这是有符号净额，不是 gross flow。页面不得把净额拆分或命名成“主力总流入/主力总流出”。

## 3. 刷新与性能

- 资金/价格序列生成轻量签名；分钟内容未变化时不重建 ECharts option。
- 数据变化时使用 `notMerge:false` 和 `replaceMerge` 只更新 grid、坐标轴与 series，避免销毁整个图表实例。
- Tooltip `transitionDuration=0`，axisPointer 关闭动画，减少 3 秒刷新期间的视觉拖尾。
- `updateAxisPointer` 记录当前分钟。若刷新发生时光标仍在 05B 内，完成增量 setOption 后通过 `showTip` 恢复同一分钟悬浮卡与联动游标。
- 页面原有交互保护仍生效：指针位于图表或页面正在滚动时，网络请求继续，但中间重绘帧可延后并只应用最新帧。
- 打开弹窗只移动同一终端 DOM，不复制 chart，不重复绑定鼠标事件。

独立测试：`tests/test_market_heatmap_05b_crosshair_ui.py`

覆盖：

- 三个 x 轴加入 `[0,1,2]` 联动组；
- 三个 grid 都配置可见、吸附的 x 轴游标；
- 悬浮卡六类字段和正负净额语义；
- 首资金点 `delta=null`；
- hover 时间保存及刷新后 `showTip` 恢复；
- 增量 setOption 与无变化跳过重绘；
- 页面内/弹窗只存在一个 ECharts 实例；
- 当天成交量为手、历史成交量为股的后端契约。

## 5. 浏览器人工验收步骤

1. 在价格区域横向移动，确认成交量区和资金区竖线与悬浮卡时间一致。
2. 分别在成交量柱和资金柱上移动，确认价格区游标同步，卡片仍显示完整六项。
3. 悬停超过一次 3 秒刷新周期，确认游标不跳回最新分钟、卡片不消失。
4. 打开 05B 弹窗重复步骤 1–3，关闭弹窗后再次验证页面内交互。
5. 检查首个资金点：本分钟变化必须为 `--` 并说明无相邻前值。
6. 选择累计资金为负的分钟：卡片必须保留负号并标注“净流出”；正数同理。
7. 实时样例可用成交额反查成交量口径：`成交额 ÷ 最新价 ÷ f56` 对普通 A 股应接近 100 股/手。
